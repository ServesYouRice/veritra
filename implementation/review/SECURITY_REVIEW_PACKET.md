# Veritra independent security review packet

Status: candidate implementation; production remains fail-closed.

## Review target

The coordinator must give the reviewer the immutable Git commit produced by
the final verification run. Review that revision only. Record the commit,
reviewer identity, dates, findings, fixes, and rerun evidence in
`RELEASE_MATRIX.md`. No finding is considered closed by this document alone.

## Frozen design surface

- Protocol: MLS 1.0 through OpenMLS 0.8.1, ciphersuite
  `MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519`.
- Application marker: `mls10-openmls-v1`; the server rejects other markers.
- Native ABI: v4 in `crypto/rust/include/veritra_crypto.h`.
- Credentials: length-prefixed account/device identity plus the MLS signature
  key; key packages are checked against expected account and device values.
- Local state: SQLite3MC ChaCha20 database with a random 256-bit key held in
  platform secure storage. MLS state, rollback counter, affected ciphertext
  rows, dedupe marker, and sync cursor commit in one transaction.
- Payloads: `VAP1`, version 1, JSON inside authenticated MLS bytes, padded to
  256-byte classes. Conversation, sender device, action ID, type, and version
  are duplicated inside the authenticated payload and checked after decrypt.
- Attachments/backups: independently authenticated AES-256-GCM chunks with
  unique keys/nonces. Attachment keys and content metadata travel only inside
  MLS payloads. Backup recovery uses a user-held 256-bit capability and
  256-bit encryption key; older recovery capabilities are invalidated.
- Revocation: server state is pending, commit-submitted, then completed only
  after every snapshotted active device confirms processing the MLS removal.
- Device link and peer verification: both use domain-separated,
  length-prefixed local transcripts. Peer safety hashes sort MLS member
  credential/signature-key records and bind group ID and epoch.
- Push: Web Push, FCM, and APNs carry only
  `new_encrypted_event_available`; no sender or content fields.
- Calls: SDP/ICE is an authenticated MLS application payload. Media uses
  WebRTC DTLS-SRTP and operator-controlled TURN; call lifecycle timing remains
  visible to the server.

## Required source review

Review at minimum:

- `crypto/rust/src/mls.rs`, `mls/state.rs`, `attachment.rs`, `ffi.rs`, `lib.rs`
- `mobile/lib/crypto/`, `mobile/lib/storage/`, `mobile/lib/calls/`
- MLS, message, attachment, backup, revocation, push, and call server paths
- migrations 0021 through 0023 and rollback/upgrade behavior
- Android/iOS native push and native crypto packaging
- `THIRD_PARTY_NOTICES.md`, lockfiles, CI, and release scripts

## Threats and mandatory failure cases

The review must attempt credential substitution, wrong conversation/group,
unknown payload version, padding/framing corruption, replay, duplicate and
out-of-order delivery, offline epoch gaps, local database wrong key, state
rollback, interrupted atomic commit, attachment reorder/truncation/wrong key,
backup rollback/wrong key/process death, revoked-device reconnect, malicious
push payloads, plaintext call metadata, and ABI ownership/panic failures.

The server is untrusted for confidentiality. It necessarily observes account,
device, membership, conversation, timing, ciphertext sizes, call lifecycle,
push-provider token, and attachment/backup size metadata. Anonymous routing,
federation, post-quantum protection, and hiding that metadata are not claimed.

## Reproduction

Use pinned toolchains and lockfiles. Run:

```sh
./scripts/lint.sh
./scripts/test.sh
./scripts/license-check.sh
./scripts/build-mobile-crypto.sh android
cd mobile && flutter analyze && flutter test && flutter build apk --release
```

On macOS additionally run `./scripts/build-mobile-crypto.sh ios`, an unsigned
release build, then the approved signing workflow. SBOM, checksums, and GitHub
provenance are generated by `.github/workflows/release.yml` only after all
gates pass.

## Release decision

Critical/high findings must be fixed and independently retested. Lower
findings require explicit residual-risk acceptance. Until the review and real
device matrix are complete, `UnavailableCryptoService` stays wired and
`PM_CRYPTO_UNAVAILABLE` remains present. `scripts/release-readiness.sh` must
continue to fail; deleting or weakening that check is not remediation.
