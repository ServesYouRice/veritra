## Starting point (checked against the code)

The STATE.md C4 row (2026-11-11 review) lists removal proofs, L1 rosters,
producers/receivers, owner cancellation, UI and server succession as
missing. Round 7 (STATE "Rounds" table) and `docs/crypto.md` ("C4 app
wiring", "C4 leave proof in the commit") had already built them; the code
confirms it: `NativeCryptoService._judgeIncomingCommit` (two-phase receive,
L1 gate, removal proofs), `_stage`/`_plannedRecord` (producers),
`app_state_roles.dart` (actions, leave proof, owner cancel, server
succession), `roles_screen.dart`. What was missing was tests of the wiring
against a hostile member ("not yet covered by tests"), two design items and
a stable read API for C2/C3.

## Changes

- `stageRoleChange` runs `validateCommit` on any builder's record before
  staging (producer rule; `GovernanceCommands` already did, other builders
  did not).
- Early handover warning (D81 design, "Clocks stay local"):
  `c4.early_win.<group>` written with a won election or claim this device's
  clocks would have refused; roles screen warns while `ownerRev` is that rev.
- Roles screen prompts the owner to mark trusted admins as electors.

  `BuiltInRole` or null, never the server's role.
- Docs: `docs/crypto.md` change log and "C4 app wiring" (producers, early
  handover, read API, two residuals); design doc status and "Round 4".
- Strings: `rolesEarlyWin`, `rolesElectorHint` (en, sr Cyrillic formal,
  sr Latin generated).

## Adversarial tests (`mobile/test/c4_adversarial_native_test.dart`)

Real OpenMLS devices; Alice (owner), Bob (admin, elector), Carol (member) on
`NativeCryptoService`; Mallory (moderator) on a raw native device that
stages any record.

| Case | Expected on every honest app | Guard |
|---|---|---|
| 10 forged records (ownership, self-promotion, member to admin, demote admin, posting switch, announcement channel, rev + 2, old rev, forged `ownerRev`, election by non-elector) | `GovernanceRefusedException(<reason>)`, record and epoch unchanged | `validateCommit` in the receiver |
| Same refusal 3 times and after a restart | still refused, committed state never held it | receiver + restore |
| Commit staged on an epoch another commit won; winner replayed | not merged, record = winner's | MLS epoch order |
| Moderator removes the admin above her with a correctly pruned record | held `removal_unproven`, twice | removal proofs |
| Admin removes the moderator | merged, moderator pruned | control |
| Leaf added under the owner's account id grants Mallory admin | held `committer_unapproved` | L1 committer gate |
| Plain member's builder returns a self-promotion | `GovernanceCommandException(hierarchy)`, nothing queued | producer check |
| D81: open refused while owner active; after 31 + 8 days open, vote, win | owner moves, no warning, succession ask saved | commands + receivers |
| D81: modified client opens and wins at once | merged everywhere, `c4.early_win` = win rev | early-win flag |
| D81: owner commits while an election is open | a commit keeping it open is refused; the owner's self-update is the cancel, `ownerRev` unchanged | `validateCommit`, `_ownerCancelRecord` |

Mutation check: each of the four guards (L1 committer gate, producer
check, removal-proof hold, receiver `validateCommit`) was removed in turn;
its test failed each time (output in the session log).

`mobile/test/c4_roles_screen_test.dart`: elector prompt shown to the owner
only while an admin is not an elector; early-handover warning shown while
`ownerRev` equals the saved rev and gone after the next owner decision;
`verifiedRoleOf` returns record roles and null for a DM whose server role
says owner.
