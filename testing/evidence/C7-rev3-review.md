Reviewer: Opus, 2026-11-06, against `main` at `f23e456`, of `docs/designs/C7-channel-history.md` revision 3. Verdict: NOT ready to build (about 80% confidence). Revision 4 answers each item. Citations were re-checked against the code on 2026-11-07 (`main` still `f23e456`); notes on that check are at the end.

Blockers:
1 HIGH removed member reads new posts: removal at E_r, add at E_r+1 lands before rekey history_sync; add-time slot hands over CHK_g; newcomer can't read rekey (sent pre-join); seals under CHK_g readable by R. Same when a rekey loses a race (only "the device" keeps the rekey-due note). Fix: every device tracks latest applied removal epoch; never hand over/seal under a generation opened before it (random key_c in slot instead); clears only on rekey with close_epoch >= that epoch; committer without chain state gives random slots that don't count as the rekey; never send a second history_sync for mode reasons (leaks one bit).
2 HIGH decision 4 ordering rules contradict ("later record with used seq is stale/ignored" vs "same seq different bytes closes channel"). Fix: same seq + same prev arriving later = stale; prev not matching this device's head, or slot record with seq <= head but different bytes = fork, close.
3 HIGH lost record leaves device believing channel still full, hands old period to newcomers (server strips one device's switch-off body -> P1 invalid row; D54 undecryptable; past-epoch limit). Fix: any invalid/undecryptable/dropped message in a group marks every full channel of that group "unsure"; unsure device hands over random keys until a later record/rekey confirms head; newcomer seeing different records across slots treats as fork (I4) not first-wins; tell admin when sender's own record doesn't come back valid.
4 HIGH nobody can verify post signature: pm_crypto_group_decrypt (crypto/rust/src/ffi.rs:1521) returns only plaintext (no sender sig key, no epoch); no FFI reads leaf keys; departed senders' keys only from server device directory. Fix: decrypt returns sender's 32-byte sig key + epoch, or verify inside Rust; add read of member key from tree; state server trust limit for departed senders or drop their posts (owner Q B).
5 MED-HIGH edits reveal posts: edit carries full text sealed under current CHK; newcomer opens it even if target is earlier/members_from_join period. Fix: seal content-bearing targeted actions under CHK only if target sealed in current period; store row period locally; else random key.
6 MED authority undefined: manage_channels / can(actor,…,channelId:) gone after C4 rescope; governance.dart has roleOf, mayPost, mayActOn only; create record has no authority rule. Fix: switch/move need admin+ (D80); create needs creator's channel-creation right; missing seq 0 = implicit members_from_join genesis, defined for vectors.
Further:
7 MED ABI 12 is C6's, C7 needs 13+ coordinated with C4; XChaCha20-Poly1305/HKDF not direct deps (owner Q A; recommend reusing direct aes-gcm + HKDF from existing crates like C6, random 96-bit nonce safe with per-body keys). "C4 takes the same export" wrong.
8 MED history_sync body unparseable as written (no signature, no VAP1, kc_c undefined). Define one layout e.g. normal body with fixed-bucket VAP1 history_sync payload followed by N slots; recompute 72+552×N size check.
9 MED flag leaks not in I5: a) kc_c from per-message slot key incl. action_id; b) retries byte-identical: keep sealed_body in outbox, include in sameIdempotentMessage (message_store.go:229), never re-seal same action_id; delete "retry re-encodes payload" line; c) always carry 32-byte key field in switch records (size buckets); d) hold edits/deletes after removal in every channel; e) forbid server paging for community conversations (chat_screen.dart:277,1142 loadOlderMessages -> listMessagePage app_state.dart:1969); GET /conversations/{id}/messages serves all envelopes with no join filter — say which route serves bodies; history route per device; f) C6 report envelope_id in clear reveals full channel — add to residuals table.
