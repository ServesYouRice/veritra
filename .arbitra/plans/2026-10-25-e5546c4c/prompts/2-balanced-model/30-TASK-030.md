<goal>
Fix two gaps in mobile/lib/core/app_state.dart so a queued MLS control message, and the application messages held behind it, cannot wait indefinitely:
- in _flushMlsOutboxOnce, a failure of completeCommitBundle or removePendingMlsMessage after a successful send must record retry state with backoff;
- _scheduleMlsOutboxRetry must arm a fallback timer when it cannot read pending messages.

This matters because it fixes:
- MLS local-finalization failures can leave no retry scheduled (medium)
  Local completion happens outside the send-error catch that records nextAttemptAt. If the server accepts a first-attempt message but local completion fails, the outer worker suppresses the error. A still-queued head with no previous nextAttemptAt is then excluded by the retry scheduler, so no retry timer is created.
</goal>
