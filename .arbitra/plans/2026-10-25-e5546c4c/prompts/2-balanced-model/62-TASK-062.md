<goal>

This matters because it fixes:
- Submission combines a stale server origin with subsequently edited credentials (high)
  <quotes> case AuthMode.join: return widget.state.registerWithInvite( raw, inviteCode.text.trim(), username.text.trim(), password.text, ); </quotes> _submit captures the URL before asynchronous preflight but reads the mode and credentials afterward. The form remains editable, and submission does not reject changes to the URL or form during either await. When the authentication mode remains unchanged, credentials entered for a newly selected server are passed to the originally captured server.
- Submit button stays enabled during _submit's pre-flight network probe, allowing duplicate owner/registration/login requests (medium)
  The submit button is disabled only by widget.state.busy. _submit performs two awaits before calling the mutating AppState operation: probeSetup, then hasStoredDeviceIdentityForOrigin. Nothing in this file sets a busy or submitting flag during those awaits. If probeSetup does not toggle busy, a second tap starts a second _submit, and both proceed to createOwner, registerWithInvite or login.
</goal>
