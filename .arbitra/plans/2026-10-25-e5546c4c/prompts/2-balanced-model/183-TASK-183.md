<goal>
Change recordDeliveredAsync and the deliveryQueue pending map in server/internal/httpapi/receipts.go so that a pending (account, conversation) candidate is replaced only by a candidate that is further along by the ordering ApplyDeliveries uses. An older sync page must no longer discard a newer pending cursor.

This matters because it fixes:
- Out-of-order sync requests can discard newer delivery cursors (medium)
  Coalescing keeps the last arriving MessageID, not necessarily the furthest delivery cursor. An older sync page arriving from another device or overlapping request can overwrite a newer pending cursor before a worker takes it. Only the replacement reaches storage; even a monotonic ApplyDeliveries implementation cannot recover the discarded newer candidate.
</goal>
