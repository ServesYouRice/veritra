<goal>
Add an in-flight registry to the recorder in server/cmd/veritra-load/stats.go and use it from the step loop in execute (workload.go), so that summarize(measureFrom, measureTo) includes every operation started in the window, including work registered with an explicit earlier start time such as a queued download. Wait within a bounded grace period for registered operations started before the window end, and count any that remain as explicit unfinished failures, each recorded exactly once.

This matters because it fixes:
- Step summaries are computed while operations started in the window are still in flight (medium)
  timed records an operation only when it completes, tagged with its start time. execute calls summarize(measureFrom, measureTo) as soon as the window ends and does not wait for operations still running. Operations that start near the end of the window and are slow, or eventually time out, are not yet recorded. If summarize selects by start time, as the recorded 'started' value suggests, these operations are never attributed to any step. The excluded operations are disproportionately the slowest ones and the errors.
