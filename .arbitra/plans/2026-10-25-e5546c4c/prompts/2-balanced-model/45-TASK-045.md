<goal>
Change BackupService.recover and _download so that a 416 on a resumed download first tries to authenticate the saved partial file, and then does one fresh download from offset 0, instead of failing as corrupt.

This matters because it fixes:
- Range rejection bypasses the stale-prefix retry (medium)
  <quotes> if (error.statusCode == 416) { // The saved prefix is not from this backup any more. await sink?.close(); sink = null; await file.delete(); throw const BackupException(BackupFailureKind.corrupt); </quotes> The fresh-download fallback catches only decryption failures. A 416 from the preceding download deletes the saved file and escapes that fallback. An already-complete partial file, or a prefix longer than a different requested backup, therefore causes a valid recovery attempt to fail as corrupt instead of authenticating locally or restarting.
</goal>
