<goal>

This matters because it fixes:
- Hard-coded string guard scans one line at a time and misses wrapped literals and common string parameters (medium)
  The T44C guard promises that a new hard-coded English string cannot slip back in, but it cannot keep that promise. 1. It runs `_literal` against each line of each file separately. The trigger (`Text`, `tooltip:`, `hintText:` and so on) must sit on the same line as the opening quote. `dart format` routinely writes `Text(` on one line and puts a long literal on the next. Neither line matches, because one has no quote and the other has no trigger keyword. Long user-facing sentences are the literals most likely to be wrapped this way. 2. The trigger list leaves out many common ways to pass user-visible text: - String `label:` arguments (NavigationDestination, BottomNavigationBarItem, Semantics). - `Tooltip(message:` and `Tab(text:`. - `errorText:`, `counterText:`, `prefixText:` and `suffixText:`. - `TextSpan(text:`. - `SelectableText(`, because `\bText` has no word boundary inside `SelectableText`. - Raw strings such as `Text(r'...')`. - Named arguments placed before the positional literal. 3. The self-test only checks single-line positive cases, so none of these gaps is covered.
</goal>
