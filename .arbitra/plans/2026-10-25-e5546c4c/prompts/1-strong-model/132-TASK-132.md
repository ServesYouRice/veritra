This matters because it fixes:
- Each advisory exception requires a 'scope', but the ignore it produces applies to the whole dependency graph (medium)

Nothing in the in-scope code limits an exception to the crate or path its `scope` describes. A scope check based on `cargo tree -i ... -e normal,build` would therefore miss dev-only, cfg-gated and inactive-optional paths that the ignore still suppresses (critique CRIT-132-AUDITED-GRAPH-COVERAGE).
