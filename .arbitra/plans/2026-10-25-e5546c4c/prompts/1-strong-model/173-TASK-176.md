<goal>
Change login and loginBackoffKeys (server/internal/httpapi/auth_handlers.go) so that failures without a valid device secret for the named account count only against the source-scoped key. The cross-source account-scoped key, keyed by username plus device_id, counts only failures that presented a valid device secret (section-255217d2d387fd53976689b2/Q-3), so a legitimate login from another source is not refused with 429. For requests without a valid device secret, nothing observable may depend on whether the password was correct.

This matters because it fixes:
- Username-only login backoff key lets anyone lock a known user out of login (medium)
  One login backoff key depends only on the lower-cased username, and RetryAfterAny rejects a request if any of its keys is in backoff. Any client from any IP, using any device_id, records failures against that key, including requests whose account lookup failed. Legitimate attempts are rejected with 429 before their correct credentials are checked.
</goal>
