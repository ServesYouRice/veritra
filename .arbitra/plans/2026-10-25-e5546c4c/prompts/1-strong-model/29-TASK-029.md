<goal>
Break the abandon/reconcile/claim/restage loop in AppState._flushMlsOutboxOnce and AppState._reconcileMlsMembership (mobile/lib/core/app_state.dart) when the server refuses a bundle with 400, 403 or 422. A 409 epoch conflict must still trigger a prompt reconcile once the epoch has changed. A change in backoff must be reconciled again automatically when its backoff expires, through an ownership-guarded wake timer, even on an idle session that receives no external events.

This matters because it fixes:
- A commit refused with 400/403/422 is abandoned and immediately staged again, with no backoff, re-claiming other devices' key packages each time (high)
  On any refused bundle, the flush abandons the commit, sets _mlsReconcileRequested, and starts a catch-up at once. Refused here means 409, 403, 400 or 422. The catch-up runs _reconcileMlsMembership, which claims key packages again and stages the same change. A coordinator acts immediately, and every device acts when coordinatorDeviceId is null. The epoch has not changed, the abandoned bundle no longer counts as pending MLS work, and staged == true triggers _flushMlsOutbox. For 400/403/422 the server refuses for the same reason again, so the loop closes. The 3-minute fallback does not apply to coordinators, and nothing records the refusal.
</goal>
