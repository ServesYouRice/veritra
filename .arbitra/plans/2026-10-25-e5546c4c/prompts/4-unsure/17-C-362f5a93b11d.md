<claim>
Unauthenticated register performs the expensive anonymous password hash before validating enrollment or invite (medium)

register calls auth.HashPasswordContext with the Anonymous class before running cheap checks. Those checks are device key package presence and size, device name, reservation signature (verifyEnrollment) and invite validity. Register has no backoff, so any anonymous client can force one full password hash per request without a valid invite or reservation. Login verification uses the same auth.Anonymous class, and a saturated hasher surfaces as 503 password_hashing_busy. createOwner has the same ordering but is gated by setup authorization.
</claim>
