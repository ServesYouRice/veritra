<claim>
Client-supplied X-Forwarded-For overrides the trusted proxy's X-Real-IP (high)

If the direct peer is a trusted proxy, ClientIP uses any non-empty X-Forwarded-For and returns its rightmost untrusted entry. It reads X-Real-IP only when X-Forwarded-For is absent. The code and its test support proxies that send the client address in X-Real-IP, and the doc comment tells operators to overwrite only X-Real-IP. Some proxies set X-Real-IP but pass the client's own X-Forwarded-For through unchanged; nginx does this by default for headers it is not told to set. Behind such a proxy, the client chooses its own resolved identity. A forged public address becomes the identity. A forged 127.0.0.1 is returned as-is when loopback is not in the trusted set. A malformed or all-trusted value falls back to the proxy's own address, which is loopback for a same-host proxy. The resolver is the identity source for throttles, setup authorization and realtime limits, so all three can be spoofed.
</claim>
