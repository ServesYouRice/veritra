<claim>
Failed opens leave the database handle open on the keyRejected and new-database paths, which can block quarantine on Windows (medium)

In the catch block of _openDatabaseLocked, the handle is closed only on the sqliteFeatureMissing and upgradeStarted paths. On the !databaseExists rethrow path and the generic keyRejected path, the handle created by _databaseFactory is dropped without close(). SQLite typically opens the file successfully even with a wrong key, and the read fails afterward. Failed opens are not cached (_openingDatabase is reset), so quarantineUnreadableDatabase has no handle to close.
</claim>
