Initial schema creation can leave an unreopenable partial database (high)

Initial creation has neither the transaction used by onUpgrade nor an in-transaction schema-version write. With Drift's nontransactional migration callbacks, an error after table creation leaves committed tables while the database version remains zero. The next open attempts creation again and encounters existing tables. A crash between successful creation and Drift's subsequent version write creates the same inconsistency.
