<claim>
Own-device commit events trust the server's sender and idempotency key, and are skipped silently when no outbox entry matches (medium)

When a 'commit' message's server-supplied senderDeviceId equals this device, the code takes one of two paths. (a) It merges the local pending commit after matching only the server-supplied idempotencyKey and the epoch. It never compares message.payload with the commit bytes in the bundle. (b) If no pending outbox bundle matches, it records the event and advances the cursor without processing anything. Path (b) is normal after completeCommitBundle has already merged. It is indistinguishable, however, from two failure cases: the commit was abandoned (pending cleared) although the server actually stored it, or the server labeled another member's commit as this device's. In both cases the device stays at the old epoch with no error.
</claim>
