JSON key casing can bypass backup counter validation (medium)

Validation decodes metadata into a Go struct, whose JSON field matching accepts case variants, but historical comparison extracts only the exact lowercase JSON key from the unchanged metadata. With an existing counter of 5, metadata {"state_counter":1,"STATE_COUNTER":6} is decoded as 6 for validation while SQLite extracts 1 from the stored document. Thus the validated counter and persisted counter can differ, bypassing the intended increasing-counter check unless additional schema validation rejects this input.
</claim>
